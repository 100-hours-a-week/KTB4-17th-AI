## 1. 한눈에 보기

1. **배포를 막을 수준의 결함이 많은 기능은 다섯이다.**
   - 온보딩 페르소나 추출: 20문제 모두 사용자가 하지 않은 말로 성향을 지어냈다.
   - 시뮬레이션 v2 리포트 서술: 절반에서 없던 말을 서술했다.
   - 카톡 말투 추출 v1: 본인이 안 쓴 표현을 말투로 적었다.
   - 시뮬레이션 v2 대본 생성: 35%가 오류로 끝났다.
   - 연습대화 답변: 카톡 말투 예시를 상대역이 실제로 한 일처럼 말했다. 이 결함을 노린 최종 시험 문제 3개 중 2개에서 나왔다(사용자 확인).
2. **회귀용·최종 시험 모두 치명 실패가 0건인 기능은 온보딩 답변 태깅 하나뿐이다.** 연습대화 답변은 회귀용에서 0건이었지만, 회귀용에 이 결함을 노린 문제가 없었기 때문이다. 최종 시험에서 3건이 나왔다.
3. **배포 게이트는 "기준선보다 나빠지면 차단"으로 정했다(사용자 승인).** 지금 수준을 기준선으로 고정하고, 치명 0건은 목표로 둔다.
4. **채점기 80개 중 34개만 사람 정답으로 검증됐다.** 40개는 검증용 문제에 실패 사례가 0~2개뿐이라 실패를 잘 잡는지 확인하지 못했다(표본 부족). 이런 유형의 수치는 참고치다.
5. **최종 시험(처음 보는 문제 8개씩)에서 특정 결함이 크게 늘어난 기능은 넷이다.** 카톡 말투 v1, 카톡 말투·점수 v2, 온보딩 질문 생성, 연습대화 답변이다.

용어
- **치명(CRIT):** 사용자에게 나가면 안 되는 결함이다. 예: 하지 않은 말 지어내기, 지시문 따르기, 개인정보 저장.
- **주요(MAJ):** 품질을 크게 떨어뜨리는 결함이다. 예: 답을 잘못 읽기, 같은 질문 반복.
- **실패율:** FAIL ÷ (FAIL + PASS)이다. 해당 없음은 뺐다.

## 3. 기능별 결과

"치명 실패 문제"는 치명 유형이 하나라도 FAIL인 문제 수다. 회귀용과 최종 시험은 **같은 코드·같은 모델**로 **다른 문제 묶음**을 푼 결과다. 회귀용은 20문제(마무리 답변 생성 21), 최종 시험은 8문제다. 분모가 다르므로 비율로 비교한다. 최종 시험은 1문제가 12.5%p라 비율이 크게 출렁인다.

## 4. 위험 기능 상세

### 온보딩 페르소나 추출
- **답에 없는 성향 서술(치명):** 회귀용 100%, 최종 시험 88%. 채점기는 검증됨이다.
  - 예: 사용자가 "혼자 정리"라고만 답했는데 "관계는 천천히 알아가는 편"이라고 적었다.
  - 예: "편하게 지내는 편"이라는 한 마디를 관계 성향 전체로 일반화했다.
- **답을 다른 질문 주제로 저장(주요):** 35% → 38%.
- **답하지 않은 항목에 점수 부여(주요):** 45% → 25%.
- 형식 규칙 위반(글자 수·카테고리 중복)도 회귀용 80%다. 이것은 경미(MIN) 유형이다.

### 시뮬레이션 v2 리포트 서술
- **대본에 없는 말 서술(치명):** 50% → 25%. 채점기는 검증됨이다.
- **하이라이트 구성 규칙 위반(주요):** 95% → 100%. 거의 항상 규칙을 어긴다.

### 카톡 말투 추출 v1
- **본인이 안 쓴 표현을 말투로 적음(치명):** 32% → **83%**(6문제 중 5). 최종 시험에서 크게 나빠졌다.
- **출력 형식 위반(치명):** 42% → 17%.
- 최종 시험 때는 SLM이 꺼져 있어 메인 LLM으로 실행됐다(5절). 나빠진 이유가 모델 차이일 수 있다.

### 시뮬레이션 v2 대본 생성
- **실행 오류:** 앱이 "화자 뒤섞임을 못 고침(503)"으로 대본 생성을 포기했다. 회귀용 7/20, 최종 시험 2/8, 검증용에서도 5/12였다. 사용자는 대본 대신 실패를 받는다.
- 이 오류 때문에 검증용 문제가 부족해, 이 기능의 채점기 10개는 모두 미검증이다. 실패율은 참고치다. 지어낸 사실 15% → 33%, 말투 문구를 사실로 씀 31% → 17%.

### 연습대화 답변
- **카톡 말투 예시를 자기 경험으로 말함(치명):** 회귀용 0%, 최종 시험 38%(8문제 중 3). 사용자가 3건 모두 실제 결함으로 확인했다(2026-10-29, `f06-practice-reply/labels/holdout_user.csv`).
  - 예: 사용자가 "주말에 뭐 했어요?"라고 묻자 "저는 주말에 등산 갔다 왔는데 다리 아파요"라고 답했다. 등산은 프로필·기억에 없고, 카톡 말투 예시 "등산 갔다 왔는데 다리 아파"에만 있다.
  - 예: "오늘 친구들이랑 보드게임 했는데 개웃기네 ㅋㅋㅋ"라고 했다. 보드게임은 말투 예시 "친구들이랑 보드게임 했어"에만 있다.
- 회귀용 20문제에는 이 결함을 노린 문제가 없었다. 그래서 회귀용 0%는 "결함이 없다"가 아니라 "검사하지 않았다"는 뜻이다. 지금 배포 게이트로는 이 결함이 늘어도 막지 못한다.

## 5. 최종 시험에서 나빠진 점

규칙은 회귀용보다 실패율이 10%p 이상 높으면 "과적합 의심"으로 표시하는 것이다. 최종 시험은 8문제라 1문제 차이가 12.5%p다. 아래는 그중 2문제 이상 차이가 나고 채점기가 검증된 유형이다.

| 기능 | 유형 | 회귀용 → 최종 시험 |
| --- | --- | --- |
| 카톡 말투 추출 v1 | 본인이 안 쓴 표현을 말투로 적음 (치명) | 32% → 83% |
| 카톡 말투·점수 추출 v2 | 상대 말투가 섞임 (치명) | 5% → 33% |
| 카톡 말투·점수 추출 v2 | 본인이 안 쓴 표현을 말투로 적음 (치명) | 20% → 50% |
| 온보딩 질문 생성 | 하루의 자기소개를 사용자 말로 읽음 (주요) | 5% → 38% |
| 메모리 사실 추출 | 말하지 않은 사실 저장 (주요) | 0% → 25% |
| 종료 메시지 생성 | 상대 말을 잘못 읽음 (주요) | 5% → 25% |

연습대화 답변의 "말투 문구를 사실로 씀(치명)"은 0%에서 38%(8문제 중 3)로 올랐다. 채점기는 미검증이지만 3건 모두 사용자가 실제 결함으로 확인했다(4절). 회귀용 0%는 이 결함을 노린 문제가 회귀용에 없었기 때문이다.

**해석할 때 주의할 점**
- **SLM 꺼짐:** 최종 시험 때 SLM(kanana) 서버가 꺼져 있었다. 온보딩 답변 태깅, 온보딩 페르소나 추출, 카톡 말투 v1은 메인 LLM으로 실행됐다. 회귀용 실행 때 SLM을 썼는지는 기록이 없다.
- **같은 사용자 재사용:** 최종 시험 문제는 새 대화 쌍이지만 사용자 일부는 다른 문제와 겹친다. 완전히 새로운 사용자 집단은 아니다.

## 6. 배포 게이트 (사용자 승인 2026-10-29)

프롬프트·모델·하네스를 바꾸면 회귀용 문제를 다시 돌린다. 아래 중 하나라도 해당하면 배포를 막는다.

1. 앱 실행 오류 건수가 기준선보다 많다.
2. 규칙 검사 통과율이 기준선보다 낮다.
3. 채점기가 검증된 치명 유형의 FAIL 건수가 기준선보다 많다.
4. 채점기가 검증된 주요 유형의 실패율이 기준선보다 10%p 이상 높다.

- 치명 0건은 목표로 둔다. 지금 0건을 요구하면 15개 중 13개 기능이 막힌다.
- 채점기가 검증되지 않은 유형은 참고만 하고 배포를 막지 않는다.
- 기능별 차단선은 각 EVAL.md 6-2에 있다.

실행 방법:

```bash
python3 evals/_harness/stage6_cli.py run-regression --only f01
python3 evals/_harness/stage6_gate.py --check f01 <새 결과 파일> --baseline-json evals/baseline_b5e158c_regression.json
```

Judge가 Claude 구독 호출(`claude -p`)이라 CI 서버에서는 그대로 돌릴 수 없다. 처음에는 바뀐 기능만 로컬에서 돌리고, CI에는 규칙 검사만(`--no-judge`) 넣기를 권한다.

## 7. 채점기 신뢰도

| 상태 | 개수 | 뜻 |
| --- | --- | --- |
| 검증됨 | 34 | 사람 정답과 TPR·TNR 0.85 이상 일치 |
| 표본 부족 | 40 | 검증용 문제에 사람 FAIL이 0~2개라 실패를 잘 잡는지 모름 |
| 일부 미채점 | 3 | 규칙 검사가 일부 문제에서 판정을 내지 않음 |
| 실행 오류로 미검증 | 3 | 대본 생성 검증용 문제 5개가 앱 오류로 실행되지 않음 |

※ 2026-10-29 사용자 결정으로 가벼운 유형 5개(온보딩 질문 생성의 없는 공통점·너무 긴 답·여러 개 질문·이모지, 연습대화의 너무 긴 답)를 평가에서 삭제해 85개 → 80개가 됐다. 가벼운 유형은 '결과 형식 규칙 위반'(온보딩 페르소나 추출)과 '정해진 분류 밖 카테고리'(메모리 사실 추출)만 남았다.

표본 부족 유형이 많은 기능은 시뮬레이션 v2 대본 생성(10개 전부 미검증), 대본 심사, 연습대화 답변이다. 이 기능들의 수치는 실제보다 낮거나 높을 수 있다.

## 8. 남은 과제 (우선순위 순)

1. **온보딩 페르소나 추출의 성향 지어내기를 고친다.** 프롬프트에서 "답에 있는 말만 옮긴다"를 강화하고 회귀용으로 다시 잰다.
2. **연습대화 답변이 카톡 말투 예시를 자기 경험처럼 말하는 문제를 고친다.** 그리고 회귀용 골드셋에 이 결함을 노린 문제를 추가한다. 지금 회귀용에는 이런 문제가 없어 게이트가 이 결함을 막지 못한다.
3. **시뮬레이션 v2 대본 생성의 "화자 뒤섞임 못 고침" 오류 원인을 찾는다.** 실행의 약 35%가 실패한다.
4. **시뮬레이션 v2 리포트 서술**의 없던 말 서술과 하이라이트 규칙 위반을 고친다.
5. **카톡 말투 v1·v2**에서 본인이 안 쓴 표현을 적는 문제를 고친다. 먼저 SLM을 켠 상태로 다시 측정해 모델 차이인지 가린다.
6. **골드셋 정리:** 카톡 말투 v1·v2에서 발화가 4개뿐인 5문제(g04-k12, g04-k04, g04-k07, g05-k04, g05-k07)를 고친다.
7. **채점기 보강:** 표본 부족 40개 유형에 실패 사례를 모아 채점기를 검증한다. 치명 유형부터 한다.
8. **최종 시험 문제 교체:** 이번에 한 번 썼으므로 다음 큰 릴리스 전에 새로 만든다.
