# 확인할 것 (이것만)
- judge_mixup: 화자 혼동. (1) a 의 줄을 b 가 말하는 것처럼 쓴 경우 — 예: a 의 줄에서 a 가 자기 닉네임을 부르거나

  예: b 프로필에 캠핑이 없는데 b 가 "저도 캠핑 좋아해요"라고 하면 혼동입니다. 자기 프로필·fact 에 근거가 있으면 혼동이 아닙니다.

### 1-3. 발견 사항

1. **심사 실패는 통과로 처리된다(fail-open).** 호출 오류·타임아웃·pass=false인데 이슈를 못 읽는 경우 모두 `passed=True, skipped=True`다(`verifier.py:568-570`, `:600-605`). 심사기가 자주 실패하면 혼동 대본이 그대로 저장된다. skipped 비율을 제품 위험 지표로 따로 잰다.
2. **규칙 검사에 걸린 대본은 심사를 받지 않는다.** (`graph.py:162-164`). 그래서 심사기의 실제 입력 분포는 "규칙을 통과한 대본"뿐이다. 골드셋도 이 분포를 따라야 운영 성능과 같은 값이 나온다.
3. **재심사는 고친 줄 주변만 본다.** 수정이 다른 줄과 새 모순을 만들어도 범위 밖이면 못 잡는다(`verifier.py:540-541`). 이 한계는 기능 15 평가에서 함께 본다.
4. **기준서가 말하는 C3(AI 자백)·C1(과거 만남)은 심사 범위에 없다.** 심사 유형은 세 가지뿐이다. 기능 12 발견 사항 3번과 같은 공백이다.
5. **JSON 모드로 도구 스키마를 흉내 낸다.** 기본 설정에서 모델이 도구 호출을 직접 하지 않고 JSON 텍스트를 낸다. 형식 실패율은 JSON 모드 기준으로 잰다.
6. **판정기 평가는 5단계 Judge 보정과 같은 방법(TPR/TNR)을 쓴다.** 사람 라벨을 정답으로 두고 유형별 TPR·TNR을 낸다.

> 출처: 2단계 판정(사용자 직접 + 사용자 기준 AI 사전 판정 🤖)과 자동 검사. 👤 검토 칸에 ✅ / ✏️(수정 내용) / 🔀(합치기·쪼개기) / ❌ 를 적어 주세요.

#### F-01 `mixup_false_positive`
- 정의: 근거가 있는 줄을 화자 혼동으로 잡는다 (fact 표기만 다르거나 'ㅋㅋ' 사용 등). 이 오탐으로 실행이 실패하기도 한다.
- Fail 판정 기준: 지적한 줄 내용이 화자 자기 프로필·fact 에 있거나 상대가 먼저 말한 것에 대한 반응이면 Fail.
- Fail 예시: v2-006-judge1, v2-014-judge1, v2-018-judge1, v2-103-judge2, v2-107-judge2, v2-110-judge1, v2-023-judge2
- Pass 예시: v2-001-judge1, v2-009-judge1
- 심각도: MAJ · 판정 방법: 정답비교 · 연결 요구사항: R-02 · 2단계 빈도: 판정 7/30
- 👤 검토: 🤖 ✅ (확정 판정 기준과 충돌 없음)

#### F-02 `missed_label_confusion`
- 정의: 라벨 a/b 를 이름처럼 쓴 진짜 화자 혼동을 놓친다.
- Fail 판정 기준: 대본에 f12 F-01 이 있는데 그 줄을 judge_speaker 로 보고하지 않으면 Fail.
- Fail 예시: v2-006-judge1, v2-020-judge1, v2-100-judge1
- Pass 예시: v2-023-judge2(0번 줄은 잡음)
- 심각도: CRIT (C5 놓침) · 판정 방법: 정답비교 · 연결 요구사항: R-01 · 2단계 빈도: 판정 3/30
- 👤 검토: 🤖 ✅ (확정 판정 기준과 충돌 없음)

#### F-03 `unresponsive_false_positive`
- 정의: 직전 말에 반응한 줄을 무반응으로 잡는다.
- Fail 판정 기준: 지적한 줄이 직전 상대 말에 답·질문·공감하고 있으면 Fail.
- Fail 예시: v2-004-judge2, v2-015-judge2, v2-114-judge1
- Pass 예시: v2-021-judge1
- 심각도: MAJ · 판정 방법: 정답비교 · 연결 요구사항: R-03 · 2단계 빈도: 판정 3/30
- 👤 검토: 🤖 ✅ (확정 판정 기준과 충돌 없음)

#### F-04 `misclassified_issue`
- 정의: 실제 문제(성향 모순)를 화자 혼동으로 잘못 분류한다.
- Fail 판정 기준: 보고한 유형이 문제의 실제 성격과 다르면 Fail.
- Fail 예시: v2-019-judge1, v2-113-judge1
- Pass 예시: v2-028-judge1
- 심각도: MAJ · 판정 방법: 정답비교 · 연결 요구사항: R-06 · 2단계 빈도: 판정 2/30
- 👤 검토: 🤖 ✅ (확정 판정 기준과 충돌 없음)

#### F-05 `output_inconsistency`
- 정의: pass=true 인데 issue 를 함께 낸다.
- Fail 판정 기준: issues 가 있는데 pass=true 면 Fail.
- Fail 예시: v2-008-judge1
- Pass 예시: v2-001-judge1
- 심각도: MAJ · 판정 방법: 코드 · 연결 요구사항: R-07 · 2단계 빈도: 코드 1/64
- 👤 검토: 🤖 ✅ (확정 판정 기준과 충돌 없음)

#### F-06 `missed_fact_owner_mixup`
- 정의: 한 사람이 상대의 fact 를 자기 것처럼 말한 줄을 놓친다.
- Fail 판정 기준: 대본 한 줄이 상대 블록의 fact 를 1인칭으로 말하는데(예: b 의 요가를 a 가 '저도 요가 시작했어요') judge_mixup 으로 보고하지 않으면 Fail.
- Fail 예시: g14-n02, g14-n08, g14-n10
- Pass 예시: -
- 심각도: CRIT (C5 놓침) · 판정 방법: 정답비교 · 연결 요구사항: R-01 · 2단계 빈도: 골드셋 대상
- 사용자 결정(질의, 2026-10-26): 추가, CRIT.
- 👤 검토: 사용자 결정(질의) 반영

### 3-2. 미분류 메모

- F-01 화자 혼동 오탐과 말투 급변(judge_tone) 지적이 f12 R-20 실패(22/46)와 f15 불필요 수정의 주된 원인이다.
- 말투 급변(judge_tone) 유형은 사용자 결정(2026-10-26)으로 삭제했다 — 말투 혼용·급변은 실패가 아니다. 기존 F-03 tone_false_positive(판정 6/30) 삭제. 심사기가 judge_tone 을 보고하는 것 자체(R-04)를 심사기 프롬프트에서 뺄지는 개선 과제로 남긴다.

### 3-3. 커버리지 공백

2단계에서 실패가 관찰되지 않아 연결된 실패 유형이 없는 요구사항: R-05, R-08, R-09, R-10. 4단계 골드셋에서 공격·경계 케이스로 확인한다.

### 3-4. 1/3/5 루브릭

해당 없음 — 이 기능의 품질 축은 Pass/Fail 로 판정한다.
