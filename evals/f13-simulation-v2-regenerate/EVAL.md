## 1. 프롬프트·코드 정리

> 재생성은 기능 12와 같은 함수(`generate_text`)·같은 프롬프트에 "이전 대본의 문제" 섹션을 더해 부른다. 시스템 프롬프트·파서·공통 규칙 검사 원문은 `evals/f12-simulation-v2-generate/EVAL.md` 1-1을 따른다. 여기에는 재생성에만 있는 부분을 적는다.

### 1-1. 원문 정리

#### (1) 재생성 진입 — `app/v2/simulation/graph.py:114-124`

```python
is_regen = st.attempts.script_calls > 0
attempts = st.attempts.model_copy(update={"script_calls": ... + 1, "regenerate": st.attempts.regenerate + (1 if is_regen else 0)})
correction = _correction(st.issues) if is_regen and st.issues else None
```

#### (2) 교정 지시문 `_correction` — `graph.py:55-60`

```python
for x in issues[:12]:
```

#### (3) 프롬프트에 붙는 섹션 — `app/v2/simulation/generator.py:302-303`

```text
- 대본 전체: format — 줄 수 14 ≠ 16
```

- 이전 대본 본문은 주지 않는다. 문제 줄 번호와 사유만 준다.

#### (4) 호출 파라미터·라우팅

### 1-2. 요구사항 목록

> 기능 12의 R-01 ~ R-19가 재생성 대본에도 그대로 적용된다. 아래는 재생성에만 해당하는 요구사항이다.

### 1-3. 발견 사항

1. **교정 지시가 이슈 12개까지만 들어간다.** 이슈가 많은 대본은 앞 12개만 전달된다(`graph.py:57`). 이슈 13번째 이후 유형은 해소율 계산에서 "전달되지 않은 이슈"로 따로 분류해야 공정하다.
2. **재생성 뒤 판정은 규칙 검사 + 전체 심사다.** `judged_full=False`로 초기화되므로(`graph.py:150`) 재생성 대본은 심사를 전체 범위로 다시 받는다. 재생성 1회의 비용(생성 1 + 심사 1)을 예산 지표에 반영한다.
3. **같은 이름 재사용 시 혼선 위험은 없다.** 재생성은 `-regenerate-text` 이름으로 분리되어 Langfuse에서 기능 12와 나눠 볼 수 있다.
4. **샘플 수확이 어렵다.** 재생성은 1차 초안이 크게 실패했을 때만 일어난다. 2단계에서는 1차 초안이 실패하도록 만든 입력(같은 닉네임, fact가 겹치는 두 사람, 짧은 프로필 등)을 의도적으로 넣거나, 저장된 실패 이슈 목록을 그대로 `correction`으로 주입해 함수를 직접 부른다.
