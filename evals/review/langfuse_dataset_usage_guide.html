질문 1

calibration이 대체 무엇인가?

calibration은 “채점 연습용 문제”라는 표시입니다. 별도 데이터셋 이름도 아니고, Langfuse 왼쪽 메뉴도 아닙니다.

사람이 몇 문제를 직접 읽고 “이 답변은 몇 점이어야 하는가”를 맞춰 보면서 자동 채점기가 너무 엄격하거나 느슨하지 않은지 조정할 때 씁니다.

질문 2

calibration은 어디에 있는가?

각 Dataset Item의 Metadata 안에 있습니다. 키 이름은 split입니다.

  1. 왼쪽 메뉴에서 Datasets 선택이미 보고 있던 화면입니다.
  2. 예: quality/persona/onboarding-tagging 선택처음 연습하기 가장 쉬운 데이터셋입니다.
  3. Items 탭에서 아무 항목의 ID를 클릭예: persona_onboarding_tagging-001
  4. Metadata를 확인"split": "calibration"이면 보정용 문제입니다.

실제 운영

실제로는 어떤 순서로 사용하는가?

  1. calibration만 소량 실행자동 채점 결과와 사람이 읽은 판단이 비슷한지 확인합니다.
  2. Evaluator 수정문장 수·라벨 일치는 코드로, 자연스러움은 LLM Judge나 사람 검토로 채점합니다.
  3. regression으로 baseline 생성현재 모델과 프롬프트의 기준 성능을 저장합니다.
  4. 후보 모델 또는 프롬프트 실행같은 문제로 다시 실행해 candidate Experiment를 만듭니다.
  5. baseline과 candidate 비교평균 점수뿐 아니라 나빠진 개별 항목의 trace를 확인합니다.
  6. blind_holdout으로 마지막 확인최종 후보가 정해졌을 때만 실행합니다.

Experiment 이름 예시

Experiment: persona-onboarding-tagging

Run 1: baseline-main-claude35
Run 2: candidate-prompt-v2-claude35
Run 3: candidate-prompt-v2-new-model

같은 Experiment 안에서 Run 이름을 다르게 만들면 Langfuse에서 전후 결과를 나란히 비교하기 쉽습니다.

실행 방식

CLI가 아니라 SDK로 실행하는 이유

CLI는 Dataset을 올리고 조회하는 데 사용했습니다. 실제 평가는 각 문제를 현재 애플리케이션 함수에 넣어야 하므로 Python SDK의 Experiment Runner를 사용합니다.

이 프로젝트에는 아직 이 실행 스크립트가 없습니다. 아래 구조의 scripts/run_quality_experiment.py를 새로 만들어야 합니다.

가장 단순한 실행 구조 보기 
from dotenv import load_dotenv
load_dotenv()

from langfuse import Evaluation, get_client
from app.features.persona.agents import TaggingAgent

langfuse = get_client()

async def task(*, item, **kwargs):
    data = item.input
    result = await TaggingAgent().tag(
        question=data["question"],
        answer=data["answer"],
    )
    return result.model_dump() if result else {"fallback": True}

def evaluator(*, output, expected_output, **kwargs):
    # 실제 구현에서는 primary/secondary/off_topic 허용값을 각각 비교
    passed = not output.get("fallback", False)
    return Evaluation(name="contract_pass", value=1.0 if passed else 0.0)

dataset = langfuse.get_dataset("quality/persona/onboarding-tagging")
calibration_items = [
    item for item in dataset.items
    if item.metadata.get("split") == "calibration"
]

try:
    result = langfuse.run_experiment(
        name="persona-onboarding-tagging",
        run_name="calibration-baseline",
        data=calibration_items,
        task=task,
        evaluators=[evaluator],
        max_concurrency=3,
        metadata={"datasetVersion": "1.12.0"},
    )
    print(result.format(include_item_results=True))
    print(result.dataset_run_url)
finally:
    langfuse.flush()
이 코드는 구조를 설명하는 최소 예시입니다. 실제 실행 파일에는 데이터셋별 앱 함수 연결, 정확한 evaluator, 실패·폴백 기록, 비용 제한이 추가되어야 합니다.

실행 후

결과는 어디에서 보는가?

  1. Langfuse 왼쪽 메뉴의 Datasets 또는 Experiments로 이동실행한 Dataset의 Run이 생성됩니다.
  2. Run을 클릭각 항목의 입력, 모델 출력, expected output, 점수를 볼 수 있습니다.
  3. 낮은 점수 항목을 클릭연결된 trace에서 실제 프롬프트, 응답, 지연시간, 토큰 사용량을 확인합니다.
  4. 두 Run을 Comparebaseline과 candidate의 평균 점수 및 항목별 변화를 비교합니다.

최소한 기록할 점수

  • contract_pass: 필수 규칙 전체 통과 여부
  • quality_score: 자연스러움·근거 충실도 등의 1~5점
  • fallback: 모델 실패 후 폴백 사용 여부
  • latency, 토큰, 비용: Langfuse trace에서 함께 비교
현재 상태

지금 바로 성능 합격 판정에 쓰면 안 되는 이유

현재 업로드 상태: draft-source-drift 데이터셋을 만들 때 기준으로 삼은 앱 코드와 현재 앱 코드가 달라졌습니다. 파이프라인 시험과 초벌 비교에는 쓸 수 있지만, 정식 배포 차단 기준으로 쓰기 전에는 기대값을 현재 코드에 맞춰 갱신해야 합니다.
  • calibration은 자유롭게 읽고 채점기를 조정해도 됩니다.
  • regression은 baseline과 후보 비교에 사용합니다.
  • blind_holdout은 현재 같은 프로젝트에 평문으로 올라가 있어 완전히 봉인된 시험은 아닙니다.
  • 330건 전체 실행은 모델 호출 비용이 발생하므로 처음에는 태깅 calibration 16건부터 시작합니다.
