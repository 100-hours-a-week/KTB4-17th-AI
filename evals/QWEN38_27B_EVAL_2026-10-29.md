# Qwen3.8 27B 성능평가 (2026-10-29)

> 기준선(gemini)과 같은 회귀용 문제로 모델만 바꿔 돌린 결과다. 모든 모델 비교는 [MODEL_COMPARISON.md](MODEL_COMPARISON.md)에 모은다.

## 한 줄 결론

**글 품질은 기준선(gemini)과 비슷하거나 조금 낫지만, 너무 느려서 지금 서버 설정으로는 운영에 쓸 수 없다.**
- 15개 기능 중 8개는 게이트를 통과했다.
- 시뮬레이션 리포트는 20건 모두 시간 초과로 기본 문구가 나갔다.
- 시뮬레이션 대본 생성은 한 건에 평균 78초(기준선 9초)가 걸렸다.

## 2. 기능별 결과

'치명 실패'는 치명 유형이 하나라도 실패한 문제의 수다. 게이트는 "기준선보다 나빠지면 차단" 규칙이다.

| 기능 | 치명 실패 (gemini → Qwen) | 게이트 | 무엇이 달라졌나 |
| --- | --- | --- | --- |
| 온보딩 다음 질문 생성 | 5 → 4 /20 | ✅ | 답을 잘못 읽는 질문 10 → 4건, 같은 질문 반복 8 → 2건으로 좋아졌다. (한 번에 여러 개 묻기 3 → 9건은 가벼운 유형이라 2026-10-29 평가에서 삭제) |
| 온보딩 답변 태깅 | 0 → 0 /20 | ⛔ | 거의 같다. 규칙 검사 89 → 86%. 3건은 응답에 `</think>` 가 섞여 JSON 을 읽지 못했다. |
| 온보딩 페르소나 추출 ⚠️ | 20 → 14 /20 | ✅ | 근거 없는 성격 서술 100 → 70%, 답 안 한 항목에 점수 매기기 45 → 5%. 프롬프트 변경이 섞여 있다. |
| 카톡 말투 추출 v1 | 12 → 10 /20 | ✅ | 대화에 없는 말투 지어내기 6 → 3건. |
| 카톡 말투·점수 추출 v2 | 4 → 8 /20 | ⛔ | 대화에 없는 말투 지어내기가 4 → 8건으로 **두 배**가 됐다. |
| 연습대화 답변 | 0 → 1 /20 | ✅ | 한 번에 여러 개 묻기 4 → 1건. 지어낸 사실 1건이 새로 나왔다. |
| 메모리 사실 추출 | 2 → 0 /20 | ✅ | AI 말을 사용자 사실로 저장하는 실수 1 → 0건, 정해진 분류 밖 카테고리 7 → 3건. |
| 메모리 충돌 판정 | 4 → 5 /20 | ✅ | 비슷하다. 기억을 잃는 판정이 4 → 5건 (채점기 표본 부족이라 참고치). |
| 시뮬레이션 대본 생성 | 7 → 10 /20 | ✅ | 앱 실행 오류 7 → 5건. 5건 중 3건은 90초 시간 초과, 2건은 화자가 섞인 대본을 끝까지 못 고친 경우다. 어색한 대사가 4 → 7건으로 늘었다. |
| 시뮬레이션 대본 재생성 | 5 → 4 /20 | ⛔ | 지적받은 문제를 못 고치거나 앞뒤가 안 맞는 대본이 60 → 85%로 늘었다. |
| 시뮬레이션 대본 심사 | 1 → 2 /20 | ⛔ | 20초 시간 초과로 1건 실패. 이름 혼동을 놓친 건이 1 → 2건. |
| 시뮬레이션 결함 줄 수정 | 5 → 9 /20 | ⛔ | 고치면서 새 문제를 만드는 경우가 5 → 8건으로 늘었다. |
| 시뮬레이션 리포트 서술 | 11 → (무효) | ⛔ | **20건 모두 30초 시간 초과(2회 시도 모두)로 앱이 기본 문구를 내보냈다.** 하이라이트가 비어 있어서 치명 실패 0건은 Qwen 성능이 아니다. |
| 채팅 마무리 답변 3개 | 3 → 1 /21 | ✅ | 없던 대화를 언급하는 실수 3 → 1건. |
| 채팅 종료 메시지 | 3 → 2 /20 | ⛔ | 내용 실수는 줄었다(없던 대화 3 → 2건, 없는 공통점 2 → 0건). 하지만 7건은 Qwen 메시지가 "일상 인사처럼 읽힌다"는 앱 검사에 걸려 대체 문구로 바뀌었고, 규칙 검사는 95 → 81%로 떨어졌다. |

요약: 게이트 통과 8개 / 차단 7개 (2026-10-29 가벼운 유형 삭제 반영 — 온보딩 질문 생성이 차단에서 통과로 바뀜). 차단된 기능 중 리포트 서술과 대본 심사는 시간 초과가 원인이다. 태깅과 종료 메시지는 내용 실수가 아니라 형식 검사(JSON 깨짐·대체 문구)가 떨어져서 막혔다.

| 기능 | gemini | Qwen | 배수 |

| 온보딩 다음 질문 생성 | 12.1초 | 38.5초 | 3배 |
| 온보딩 페르소나 추출 | 4.7초 | 16.5초 | 4배 |
| 카톡 말투·점수 추출 v2 | 2.6초 | 21.6초 | 8배 |
| 연습대화 답변 | 1.3초 | 5.3초 | 4배 |
| 메모리 충돌 판정 | 2.6초 | 17.7초 | 7배 |

전체 기능이 3~9배 느리다. 문제를 하나씩 순서대로 보냈는데도 느렸으므로, 실제 사용자가 동시에 쓰면 더 느려진다.

## 5. 판단과 다음 단계

**모델 크기를 줄이는 것은 권하지 않는다.** 내용 품질은 이미 gemini 와 비슷한 수준이라, 작은 모델로 바꾸면 품질만 떨어질 가능성이 크다. 문제는 속도다.

속도 문제를 확인할 방법:
1. **서버 설정 조정 후 다시 측정**
   - 컨텍스트를 196608 에서 16384~32768 로 줄인다.
   - 동시 처리 슬롯을 늘린다(`-np 4` 등).
   - 더 빠른 GPU(L40S·H100)를 쓰거나 서빙 엔진을 vLLM 으로 바꾼다.
2. **품질만 공정하게 보려면** 앱 시간 제한을 실행할 때만 늘려 리포트 서술을 다시 돌린다. 예: 리포트 30초 → 120초. 리포트 서술 20문제만 다시 돌리면 된다.
3. **기능별로 모델을 나눠 쓰는 방법**도 있다. 메모리·채팅 마무리처럼 Qwen 이 나았던 기능만 Qwen 을 쓰고, 시뮬레이션 v2 는 gemini 로 둔다. 다만 앱은 지금 v1·v2 단위로만 모델을 나눌 수 있다.

채점기가 '표본 부족'인 유형의 수치는 참고치다. Qwen 은 최종 시험(blind_holdout)을 돌리지 않았다.
