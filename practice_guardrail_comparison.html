연습대화(Practice v1·v2) 가드레일: 입력~프롬프트·격리LLM~출력 다이어그램 & 코드 비교

Archify Explainer 6단계 기준 · 사용자 입력 → 프롬프트 Input(격리 여부) → LLM 호출 → Output 검증 → 재생성/폴백 → 로그

현재 연습대화(v1·v2)는 사용자 입력을 무검증으로 받아 단일 문자열 프롬프트에 합쳐 LLM을 부르고(③ 프롬프트·LLM), 응답이 다 끝난 뒤 정규식 하나로 후처리(④ 정규식 검사)하는 구조입니다.
개선 구조는 ① 입력 가드레일 → ② 세션·표면 정책 라우터 → ③ 지시/데이터 경계가 분리된 격리 LLM → ④ 다중 출력 검증(안전·PII·어근 근거) → ⑤ System 교정 재생성 → ⑥ 비식별 감사 로그로 바뀝니다.
분석 범위: 연습대화 v1 (app/features/practice) & v2 (app/v2/practice) 코어 엔진: app/core/guardrail/* 원본 코드 무수정 (비교·설계 문서)
  • A
    프롬프트·LLM vs 격리된 LLM 핵심 차이: 현재는 SYSTEM_TEMPLATE + 프로필 + 메모리 + practice_cove_addon을 단순 문자열로 이어 붙이고, 재생성 교정문([CORRECTION NOTICE])을 role="user" 대화 이력에 섞어 넣습니다. 개선안은 시스템 지시와 비신뢰 데이터(프로필·메모리·사용자 입력)를 구조적 태그로 분리하고 교정 지시를 system에만 격리합니다.
  • B
    입력(Input) ~ 출력(Output) 가드레일 위치 변화: 현재는 stream_reply()에서 사용자 입력을 바로 DB에 저장하고 출력 전문이 완성된 뒤에야 검사합니다. 개선안은 DB 저장 및 LLM 호출 전 입력 가드레일을 먼저 통과시키고, 출력에서는 shadow 사후 변조 버그(without_identity_confession)를 제거합니다.
