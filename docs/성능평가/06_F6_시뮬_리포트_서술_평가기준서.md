## 1. 프롬프트 요구사항 및 코드 스키마 분석

### 1.1 입출력 형식 및 스키마 상한
* **입력**:
  - 화자 A, B의 페르소나 프로필 및 성향 점수 (`PersonaResponse`)
  - **코드가 미리 계산한 영역별/차원별 궁합 점수** (`FitResult`, 이상형 3차원은 `None` 상태)
  - 가상 소개팅 대화록 전체 (`Transcript`)
* **출력 스키마 (`ReportNarrative`) 제약 대조**:

| 필드 | 프롬프트 권장 목표 | Pydantic 스키마 하드 상한 (`ReportNarrative`) | 위반 시 런타임 동작 |
| :--- | :--- | :--- | :--- |
| `headline` | 20자 내외 한 줄 | `max_length=60` | 60자 초과 시 ValidationError -> **템플릿 폴백** |
| `summary` | 3~5문장 | `max_length=800` | 800자 초과 시 템플릿 폴백 |
| `area_comments` | 5대 영역별 1~2문장 | `dict[str, str]` (intimacy, communication, conflict, ideal, orientation) | 키 누락 시 조립 시 빈 문자열 처리 |
| `highlights` | 3~5개 (click/friction 혼합) | `list[TurnHighlight]` (최소 0, 최대 6개) | 7개 이상 시 템플릿 폴백 |
| `highlights.quote` | 대화록 원문 그대로 | `max_length=200` | 200자 초과 시 템플릿 폴백 (긴 발화는 부분 인용 필수) |
| `strengths` / `cautions` | 각 2~3개 | `list[str]` (각 최대 5개) | 5개 초과 시 템플릿 폴백 |
| `date_comment` | 추천 데이트 1~2문장 | `max_length=300` | 300자 초과 시 템플릿 폴백 |
| `ideal_fit` | 0~100 정수 또는 `null`/키 생략 | `dict[str, int \| None]` (ideal_warmth, ideal_vitality, ideal_status) | 음수나 150도 스키마는 통과 (코드에서 감점 대상) |

### 1.2 핵심 불변식 (Invariants)
1. **점수 불변성 (비-JUDGED 차원 불변)**:
   * 코드가 사전에 계산한 고유 성향 점수 및 비-이상형 영역 점수를 모델이 임의로 위변조하지 않음.
   * 서술 텍스트(`summary`, `area_comments` 등) 안에서 실제 코드 점수와 상충되는 숫자를 날조하지 않음.
2. **이상형 3차원(`ideal_*`) 산정 원칙**:
   * 유일하게 모델이 산정하는 값은 `ideal_warmth`, `ideal_vitality`, `ideal_status` 3개뿐임 (0~100 정수). 근거가 없으면 키를 생략하거나 `null`로 지정.
   * 모델이 반환한 `ideal_fit`은 `assemble_report`에서 다시 `score_layer`로 전달되어 ideal 영역 점수와 최종 총점(`overall_score`)을 갱신하는 것이 정상 동작임.
3. **하이라이트 인용 검증**:
   * `highlights.quote`는 해당 `turn_index`의 대화 발화 원문(`turns[turn_index].text`)의 **부분 문자열(Substring)과 100% 일치**해야 함.
4. **인물 전도 금지 (공통 치명 C5)**:
   * A의 발언, 성향, 취미를 B의 것으로 뒤바꿔 서술하지 않음.
5. **어조 및 서술 톤**:
   * 양측 모두에게 전달되는 분석 리포트이므로 한쪽을 일방적으로 깎아내리거나 비난하지 않음.
   * 한국어 "~해요" 체 존댓말. 조언은 구체적인 행동 단위로 제시.
   * 신뢰도 `LOW`인 차원은 "아직 잘 모르겠지만" 톤으로 유보적 서술.

## 2. 모델 점수와 제품 점수의 분리 집계

00 공통 가이드라인 2절에 따라 모델 점수와 제품 점수를 분리하여 집계함:

| 구분 | 평가 대상 데이터 | 평가 목적 및 게이트 적용 |
| :--- | :--- | :--- |
| **모델 점수 (Model Score)** | 하이라이트 인덱스 필터 및 `cautions[:5]` 슬라이스 이전의 **`ReportAgent.write` 원본 JSON** | 배포 게이트 대상 (C5 점수 모순, C5 인물 전도, 가짜 인용 0건 및 1/3/5 정성 루브릭 채점) |
| **제품 점수 (Product Score)** | 하이라이트 유효범위 필터 및 규칙 위험 caution이 병합된 최종 `MatchingReport` | 사용자 최종 전달 리포트 품질 모니터링 (모델 점수와 절대 합산/평균 금지) |
| **템플릿 폴백 (Template Fallback)** | `narrative_source=template` 발생 건 (타임아웃, 스키마 초과, 가드레일 차단 등) | 모델 품질 점수 분자에서 제외하고 기술 실패율 분모에 가산 (5% 이하) |

*(필수 표기: 모든 평가 결과표에 `GUARDRAIL_MODE`(`shadow`/`enforce`/`off`) 및 폴백 발생 사유(`timeout`, `invalid_json`, `invalid_narrative`, `guardrail`)를 명시)*

## 3. 오류 분류 체계 및 가이드라인

### 3.1 결함 분류표

| 등급 | 오류 코드 | 명칭 | 정의 및 판정 기준 | 예시 |
| :--- | :--- | :--- | :--- | :--- |
| **공통 치명 (C5)** | **E6-CRIT-01** | 점수 모순 날조 | 본문 서술에서 코드 계산 점수와 명백히 다른 숫자를 날조 기술 | 계산 점수 80점인데 서술에서 "50점으로 낮음" 단정 |
| **공통 치명 (C5)** | **E6-CRIT-02** | 인물 전도 | A와 B의 성향, 직업, 발언 주체를 뒤바꿔 서술 | A가 한 말을 B가 말했다고 서술하거나 취미 뒤바꿈 |
| **치명 (Critical)** | **E6-CRIT-03** | 가짜 인용 날조 | 대화록 원문에 존재하지 않는 문장을 `quote`로 인용 | 대화록에 없는 말을 따옴표로 날조 인용 |
| **중대 (Major)** | **E6-MAJ-01** | 일방적 비하/비난 | 한쪽 화자에게만 일방적인 결함/책임으로 서술 | "B님이 너무 배려가 없어서 매칭이 실패했습니다" |
| **중대 (Major)** | **E6-MAJ-02** | 턴 인덱스 불일치 | 인용 텍스트는 원문에 있으나 `turn_index`가 엉뚱한 턴을 가리킴 | 5번 턴 발화인데 `turn_index: 1` 표기 |
| **중대 (Major)** | **E6-MAJ-03** | ideal 점수 범위 이탈 | `ideal_*` 값이 0~100 범위를 벗어남 (스키마 통과 후 코드 오류 유발) | `ideal_warmth: 150` 또는 음수 |
| **중대 (Major)** | **E6-MAJ-04** | LOW 차원 단정 | 신뢰도 `LOW`인 차원에 대해 유보적 톤 없이 단정적 단언 | "두 분은 가치관이 전혀 맞지 않습니다" (신뢰도 LOW인데 단정) |
| **경미 (Minor)** | **E6-MIN-01** | 하이라이트 개수/구성 미흡 | `highlights`가 3개 미만 또는 6개 초과, click/friction 한쪽 쏠림 | 인용이 1개뿐이거나 click만 4개 구성 |
| **경미 (Minor)** | **E6-MIN-02** | 권장 길이 초과 | `headline`이 권장 20자를 초과(30~60자)하거나 summary가 5문장 초과 | 50자 장문 헤드라인 (단, 60자 초과는 스키마 파괴로 템플릿 폴백) |

### 3.2 자동 검증 오라클 (Automated Oracles)
1. **`ruleNonJudgedScoresUnchanged`**:
   - `Fit.JUDGED` 차원을 제외한 모든 차원 점수가 LLM 호출 전 계산값과 100% 일치하는지 검사.
2. **`quoteSubstringMatching`**:
   - `highlights`의 모든 `quote`가 `transcript.turns[turn_index].text`의 부분 문자열인지 100% 검사. 불일치 시 E6-CRIT-03.
3. **`perspectiveSwapHeuristic`**:
   - `_report_perspective_swap` 탐지기를 보조 신호로 실행하여 전도 의심 구간을 사람 검토 큐로 전달.

## 4. 정성 평가 1 / 3 / 5 루브릭 앵커

리포트 서술은 메신저 구어체 앵커가 아닌 **분석 보고서 전용 루브릭 앵커**를 적용함:

| 평가 축 | 1점 (불가 / Fail) | 3점 (보통 / Acceptable) | 5점 (우수 / Excellent) |
| :--- | :--- | :--- | :--- |
| **장면 연결성 (Scene Continuity)** | 점수의 근거를 대화록과 무관하게 지어내거나 대화 장면 설명이 없음. | 점수와 대화록의 발언을 매칭하여 설명하나 다소 건조한 요약에 그침. | 대화록 속 결정적 순간(티키타카, 템포 차이)을 정확히 포착하여 점수의 당위성을 입체적으로 해설함. |
| **양쪽 균형성 (Fair Balance)** | 한쪽 화자의 탓으로 돌리거나 일방적인 비난/비하 서술이 포함됨. | 양쪽 화자의 성향 차이로 서술하나 미세하게 한쪽의 양보만 요구함. | 두 사람의 성향 차이를 상호 존중 관점에서 균형 있게 다루며 중립적이고 따뜻한 톤을 유지함. |
| **유보 어투 (Hedging)** | 신뢰도 `LOW` 차원을 단정적으로 서술하거나 전제를 무시함. | 신뢰도 `LOW` 차원에 대해 "아직은" 등 기본적인 유보 표현을 덧붙임. | 데이터가 부족한 차원을 세련되게 유보하면서, 앞으로 더 알아가면 좋을 관전 포인트를 매끄럽게 제안함. |
| **조언 구체성 (Actionable Advice)** | "서로 노력하세요" 같은 무의미하고 추상적인 조언만 나열함. | 프로필 데이트 취향을 참고하여 일반적인 데이트 코스를 추천함. | 두 사람의 성향 교집합과 갈등 포인트를 고려하여 당장 실천할 수 있는 구체적 행동 팁을 제시함. |

## 5. 배포 게이트 합격 기준 (Gate Policy)

본 게이트는 **골드셋 확정 및 도메인 전문가 2인 앵커 승인 후** 공식 적용됨.

### 5.1 사전 차단 (Gate 1 - 치명 결함 0건)
- 대상: **모델 원문 `ReportNarrative`**
- 조건:
  * 본문 점수 모순(E6-CRIT-01): **0건**
  * 인물 전도(E6-CRIT-02): **0건 (사람 2인 교차 검증)**
  * 가짜 인용문 날조(E6-CRIT-03): **0건 (오라클 자동 검사)**

### 5.2 기술 안정성 (Gate 2)
- 조건:
  * 정상 대화록 기준 템플릿 폴백 비율 **5% 이하** (`narrative_source=template` 기준 집계)
  * 호출 타임아웃(60초) 초과율 **0%**

### 5.3 최종 품질 합격 (Gate 3 - 24건 신규 회귀 집합)
- 대상: **신규 구축 예정인 `simulation_narrative` 24건**
- 조건:
  * 4개 평가 축 전 축에서 **평균 3.0점 이상 (5점 만점)**
  * 1점(불가) 판정을 받은 리포트 **0건**
