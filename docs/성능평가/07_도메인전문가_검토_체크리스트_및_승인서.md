# [공통] 도메인 전문가 검토 체크리스트 및 배포 게이트 승인서

작성일: 2026년 10월 07일  
버전: v1.0.0  
문서 목적: 5단계 성능평가 프레임워크의 마지막 단계로서, F1~F6 기능별 평가기준서(v1.1.0) 및 골드셋 초안을 도메인 전문가(소개팅/데이팅 도메인 기획자, 연애 상담 전문가, 서비스 기획자 등)가 검토하고 공식 배포 게이트로 승인하기 위한 기준서.

---

## 1. 검토 절차 및 기본 원칙

1. **초안의 성격**: 현재 구축된 평가기준서(v1.1.0)와 골드셋은 프롬프트 요구사항 분석과 코드/데이터셋 실측 분석을 거친 **'기술적 초안'**입니다.
2. **도메인 전문가의 역할**: 
   - 모델의 기대 응답이 실제 20~30대 소개팅/데이트 상황에서 사용자가 만족할 만한 대화인지 검증합니다.
   - 각 평가 축(사실성, 이어가기, 조건, 말투 등)의 **1 / 3 / 5점 앵커 문장**이 실무적인 눈높이에 부합하는지 확인합니다.
3. **독립 평가자 2인 원칙**: 
   - 도메인 전문가 2인(Reviewer A, Reviewer B)이 독립적으로 검토를 진행하며, Calibration 세트에서 두 사람의 판정 일치도(Kappa 계수 또는 단순 일치율)가 **85% 이상**이어야 해당 척도가 고정됩니다.

## 2. 기능별 도메인 검토 체크리스트

### [F1] 온보딩 발화 검토 항목
- [ ] 온보딩 인터뷰어(AI)의 질문이 사용자의 성향과 라이프스타일을 자연스럽게 이끌어내는가?
- [ ] 첫 턴 인사(`start`)에서 부담스럽지 않고 답하기 쉬운 도입 질문을 던지는가?
- [ ] 정체 유도 질문("너 AI야?")에 대해 정체를 자백하지 않고 온보딩 목적을 매끄럽게 안내하는가?
- [ ] 이전 답변에 대해 구체적인 키워드로 호응한 후 다음 질문으로 넘어가는가? (빈 반응 "그렇군요" 방지)

### [F2] 온보딩 태깅 검토 항목
- [ ] 19개 성향 차원(연락 빈도, 애정 표현, 갈등 해결 등)의 분류가 데이팅 도메인에서 상호 배타적이고 타당한가?
- [ ] 사용자의 한 문장 답변에서 과도하게 점수를 넘겨짚지 않고 실제 드러난 텍스트 근거만 태깅하는가?
- [ ] 반어법, 농담, 이중적 표현을 문맥에 맞게 올바르게 해석하였는가?

### [F3] 페르소나 추출 검토 항목
- [ ] 3~10턴의 짧은 대화록만으로 산출된 19개 차원 점수(0~100)가 실제 사용자의 성향을 납득 가능하게 반영하는가?
- [ ] 대화에서 언급되지 않은 차원에 대해 억지로 추정하지 않고 `scores=null`, 신뢰도 `LOW`로 유보하는 것이 적절한가?
- [ ] 추출된 닉네임, 관심사, 데이트 취향 키워드가 메신저 프로필용으로 자연스러운가?

### [F4] 연습 답변 검토 항목 (골드셋 10건 재작성분 포함)
- [ ] 상대 페르소나("{partner}") 본인으로서 1인칭 구어체("저 다온이에요 ㅎㅎ")가 어색하지 않은가?
- [ ] 정체 공격 질문에 대해 연기나 AI임을 밝히지 않고 자신의 프로필 일상을 얹어 자연스럽게 방어하는가?
- [ ] 반말 요구를 받았을 때 무례하지 않게 존댓말을 방어("ㅎㅎ 저는 이게 편해요")하는 방식이 적절한가?
- [ ] 1~3문장의 짧은 메신저 호흡과 2~3턴에 1회 질문하는 빈도가 실제 소개팅 톡과 유사한가?

### [F5] 시뮬 한 줄 검토 항목 (신규 72줄 대화셋)
- [ ] 화자 A와 B가 턴 단위로 주고받는 티키타카가 실제 20~30대의 소개팅 대화처럼 자연스러운가?
- [ ] 첫 줄 인사(`OPENER`), 중반 취향 교류(`middle`), 마무리 작별(`close`)의 호흡이 자연스러운가?
- [ ] 마지막 왕복 이전에 뜬금없이 "나중에 봐요, 잘 자요"라고 작별하는 어색함이 없는가?
- [ ] 상대방의 프로필 정보를 미리 알고 있는 것처럼 날조하지 않고, 대화록에서 나온 말만 받아치는가?

### [F6] 시뮬 리포트 서술 검토 항목 (신규 24건 케이스)
- [ ] 리포트가 대화록의 특정 장면(인용문)을 들어 궁합 점수의 이유를 납득 가능하게 설명하는가?
- [ ] 두 사람 모두에게 공개되는 리포트로서 한쪽 화자를 일방적으로 깎아내리거나 비난하지 않는가?
- [ ] 신뢰도가 낮은 차원(`LOW`)에 대해 "아직은 잘 모르겠지만" 톤으로 세련되게 유보하는가?
- [ ] 추천 데이트 및 조언이 "노력하세요" 같은 상투적 문구가 아니라 구체적인 행동 단위로 제시되는가?

## 3. 1 / 3 / 5 정성 루브릭 앵커 검증표

도메인 전문가 2인은 아래 기준에 따라 각 축의 판정 앵커를 실측 평가에 적용합니다:

| 등급 | 판정 기준 | 서비스 적용 가능 여부 |
| :---: | :--- | :---: |
| **1점 (Fail)** | 치명/중대 결함이 발생했거나, 데이팅 맥락을 심각하게 훼손하여 사용자가 불쾌감이나 이질감을 느낌. | **배포 불가 (게이트 탈락)** |
| **3점 (Acceptable)** | 특별한 감동이나 탁월함은 없으나, 규정을 지키고 무난하게 대화/서술이 이어져 서비스 사용에 무리가 없음. | **배포 가능 최소 기준** |
| **5점 (Excellent)** | 20~30대 메신저 특유의 설레는 뉘앙스를 완벽히 살리거나, 심도 있고 통찰력 있는 매칭 분석을 제공함. | **우수 (골드 레퍼런스)** |

## 4. LLM Judge 도입 승인 요건

인력 리소스 절감을 위해 향후 회귀 집합(Regression Set) 평가에 LLM Judge를 보조 채점자로 투입할 경우 아래 요건을 충족해야 합니다:
1. **Calibration 일치도 테스트**:
   - `calibration` 분할 데이터에 대해 사람 2인(Reviewer A, Reviewer B)의 합의 판정과 LLM Judge의 판정을 대조.
   - 1/3/5점 일치율 또는 가중 카파(Quadratic Weighted Kappa) 계수 **0.85 이상** 확인 필수.
2. **단독 판정 금지**:
   - 일치도 85% 미달 시 LLM Judge 단독으로 배포 게이트를 통과시킬 수 없으며, 반드시 사람 2인 검토 결과를 우선함.
