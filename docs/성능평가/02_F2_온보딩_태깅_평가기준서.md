## 1. 프롬프트 요구사항 분석

### 1.1 입출력 형식 및 제약
* **입력**: 질문(`question`) 문자열, 답변(`answer`) 문자열.
* **출력 형식**: 순수 JSON 객체 (설명·마크다운 금지).
  ```json
  {"primary": [], "secondary": [], "off_topic": false}
  ```
* **라벨 풀**: 실제 코드([`app/features/persona/schemas.py`](file:///Users/hrun/Documents/ktb4-17/KTB-17DEV/app/features/persona/schemas.py))에 정의된 **총 19개 차원 목록** (`ALL_DIMENSIONS` = `SCORED` 15개 + `TEXTUAL` 4개).
  * **점수형 15개**: `contact_rhythm`, `anxiety`, `avoidance`, `disclosure`, `openness`, `engagement`, `withdrawal`, `problem_solving`, `positivity`, `assurances`, `compliance`, `seriousness`, `ideal_warmth`, `ideal_vitality`, `ideal_status`
  * **텍스트형 4개**: `interests`, `routine`, `date_prefer`, `date_avoid`

### 1.2 태깅 판정 기준
1. **`primary`**: 사용자의 답변이 직접적으로 증거/근거를 제공하는 차원 목록.
2. **`secondary`**: 답변 맥락에서 간접적으로 추론 가능한 차원 목록.
3. **`off_topic`**: 질문과 완전히 무관한 딴소리이거나 욕설/장난 발화인 경우 `primary`와 `secondary`를 모두 빈 배열(`[]`)로 두고 `true`로 설정.
4. **점수 금지 규칙**: "점수는 매기지 마세요. 어떤 차원인지만 고릅니다." 점수 키 생성을 엄격히 금지.

## 2. 기존 데이터셋 및 샘플 검토

### 2.1 기존 데이터셋 현황
- 총 80건: calibration 16건, regression 48건, blind_holdout 16건.
- 구분: 79건 `label_accuracy`, 1건 `code_behavior` (장애 주입 시 폴백 확인용 `tagging-080`).

### 2.2 발견된 결함 및 쟁점 사례

#### 쟁점 1: 단답형/무성의 답변의 `off_topic` 해석 충돌 (보류 4건)
* **대상 케이스**: `persona_onboarding_tagging-011`, `019`, `063`, `075`
* **현황**:
  사용자가 "네", "몰라요", "그냥요"처럼 극도로 짧거나 불성실하게 답한 경우, 최소 답변으로 보고 약한 primary를 줄 것인지, `off_topic: true`로 볼 것인지 해석이 갈려 `reviewFlags`에 묶여 있음.
* **조치**: 사람 2인의 확정 라벨 합의 전까지는 **회귀 게이트 일치율 분모에서 제외** 처리.

#### 쟁점 2: 코드의 자동 필터링으로 인한 환각(Hallucination) 은폐 방지
* 서비스 코드([`agents.py:583`](file:///Users/hrun/Documents/ktb4-17/KTB-17DEV/app/features/persona/agents.py#L583))가 `[d for d in raw.get("primary", []) if d in valid]`로 유효 차원 외의 문자열을 사후 제거함.
* 따라서 평가는 서비스 필터링 전 **모델 raw JSON**을 검사하여 유령 차원 생성을 감지해야 함.

## 4. 기존 데이터셋 정비 및 모수 분할

### 4.1 회귀 게이트 유효 모수 (43건)
- 전체 80건 중 회귀(`regression`) 48건에서 아래 항목을 분리:
  * 장애 주입 `code_behavior` 1건(`tagging-080`): 모델 평가 제외.
  * 단답형 보류 4건(`011`, `019`, `063`, `075`): 사람 2인 합의 전까지 분모 제외.
  * **회귀 자동 일치율 실제 분모 = 43건**.

### 4.2 자동 검증 오라클 (`autoMetrics`)
* `primaryMatch`: 기대 라벨 또는 `acceptableAlternatives`와의 집합 일치.
* `offTopicMatch`: `off_topic` 불리언 값의 정확 일치.
* `noInvalidDimensionKeys`: raw JSON에 유효 19개 차원 외의 키가 없는지 검증 (100% 필수).
