## 1. 실험 배경 및 목적

별이삼샵 AI 서버의 사용자 페르소나 메모리 RAG (v2)에서는 사용자의 대화 기록에서 코어 프로필과 세부 사실(Fact)을 추출·저장하고, 실시간 연습대화 시 가장 관련된 기억 Top-5를 찾아 프롬프트에 주입합니다.

이 과정에서 텍스트 임베딩 모델은 두 가지 핵심 경로를 담당합니다:
1. **실시간 검색 경로 (`chat_graph`의 `retrieve` 노드)**: 사용자가 메시지를 전송했을 때 수십 ms 이내에 질의를 임베딩하여 `pgvector`에서 가장 관련성이 높은 기억을 조회해야 함 (TTFT 최소화).
2. **백그라운드 메모리 그래프 (`memory_graph`의 `reconcile_node`)**: 새로 추출된 사실과 기존 사실의 코사인 유사도를 계산하여 **동일 사실(`NOOP` >= 0.99)**, **모순/업데이트(`LLM Judge` >= 0.70)**, **신규 사실(`ADD` < 0.70)** 로 명확히 분기해야 함.

본 벤치마크에서는 가이드 기준 모델인 **`KURE-v1` (ONNX int8)** 및 **`EmbeddingGemma 2`**, **`KURE-v2`**, **`ko-embed-v0`**, **`Qwen3-Embedding-4B`**, **`sionic-ai/comsat-embed-ko-8b-preview`** (8B 파라미터) 총 6종의 모델을 동일한 환경에서 직접 실측하여 최적의 모델을 검증·도출했습니다.

### 2.1 어떤 걸로 측정했는가? (데이터셋 및 하드웨어 환경)

#### ① 하드웨어 및 런타임 환경
- **머신 스펙**: Apple Silicon Mac (24 GB 통합 메모리, SSD 120GB+ 여유)
- **CPU 런타임**: GPU 가속(CUDA/MPS)을 배제하고 프로덕션 백엔드 컨테이너의 CPU 서빙 환경을 모사 (`intra_op_num_threads=2`).
- **소프트웨어 스택**: Python 3.12, `onnxruntime==1.30.0` (INT8 양자화 모델), `torch==2.2.0`, `transformers>=4.51.0`, `sentence-transformers>=2.7.0` (PyTorch bfloat16 모델).

#### ② 도메인 평가 데이터셋 (`eval_dataset.json`, 총 140개 텍스트)
소개팅 및 연습대화 도메인의 실제 한국어 구어체 특성을 반영하여 3개 세트로 직접 구축했습니다:
1. **Fact 코퍼스 (60개)**: 사용자가 등록할 수 있는 페르소나 기억 문장 60종.
   - 구성: 취미/여가(13개), 일상/생활패턴(18개), 연애관/이상형(11개), 가치관/성향(8개), 직무/과거이력(10개).
2. **구어체 평가 질문 (50개)**: Fact 문장과 단순 키워드(단어)가 직접 겹치지 않는 한국어 구어체 질문.
   - 예시 1 (줄임말/식성): `"호불호 갈리는 고수나 민초 좋아하시는 편이에요?"` ↔ Fact: `"민트초코 아이스크림과 고수가 들어간 쌀국수를 매우 좋아한다"`
   - 예시 2 (갈등 해결): `"연인이랑 다투거나 서운한 일이 생기면 어떻게 푸는 편이에요?"` ↔ Fact: `"갈등이 생겼을 때 감정을 바로 쏟아내기보다 생각을 정리한 뒤 대화로 풀고 싶어 한다"`
   - 예시 3 (음주 성향): `"술자리는 자주 가지시는 편인가요?"` ↔ Fact: `"술은 거의 못 마셔서 회식 때도 논알콜 음료나 탄산수를 마신다"`
3. **Reconcile 문장 쌍 (30쌍 = 60개 문장)**:
   - **`Paraphrase` (10쌍)**: 동일 의미의 다른 표현 (`NOOP/PROMOTE` 대상, 유사도가 매우 높아야 함).
     - 예: `"판교 IT 기업에서 백엔드 개발자로 근무 중이다"` ↔ `"직업은 IT 회사 백엔드 엔지니어이다"`
   - **`Update/Contradict` (10쌍)**: 동일 주제이나 수치나 상태가 변경/모순된 문장 (`LLM Judge` 대상).
     - 예: `"현재 골든리트리버 한 마리를 키우고 있다"` ↔ `"강아지를 키우지 않고 고양이를 키운다"`
   - **`Unrelated` (10쌍)**: 전혀 관련이 없는 서로 다른 도메인의 사실 (`ADD` 대상, 유사도가 낮아야 함).
     - 예: `"주말마다 등산 동호회에 참여한다"` ↔ `"미국 지수 ETF에 적립식으로 투자한다"`

### 2.2 어떻게 측정했는가? (측정 파이프라인 및 워크플로우)

```
[평가 데이터셋]
   ├── 60개 Fact 코퍼스 ──► [Model Document Encode] ──► doc_embs: (60, Dim)
   │                                                           │
   ├── 50개 평가 질문  ──► [Model Query Encode]    ──► q_embs:   (50, Dim)
   │                             │                             │
   │                             ▼                             ▼
   │                    [Cosine Sim Matrix] ◄──────────────────┘
   │                             │ (50, 60 행렬)
   │                             ▼
   │                    [정답 Fact 순위 산출] ──► Recall@1, Recall@3, Recall@5, MRR@5, Margin
   │
   ├── 30쌍 Reconcile ──► [A/B 문장별 임베딩] ──► 코사인 유사도 ──► Paraphrase / Contradict / Unrelated 점수 분포 및 Gap
   │
   └── 단일 질의 / 배치 ──► [time.perf_counter()] ──► 워밍업 후 수회 측정 ──► Latency P50, P95 (ms)
```

1. **문서 및 쿼리 인코딩**:
   - 60개 Fact 문장을 배치 인코딩하여 L2 정규화된 문서 행렬 $\mathbf{D} \in \mathbb{R}^{60 \times d}$ 생성.
   - 50개 질문을 모델별 프롬프트 규격(Qwen3/comsat-8b: `prompt_name='query'`, Gemma: Task Prefix, KURE: 프롬프트 없음)에 맞춰 인코딩하여 질문 행렬 $\mathbf{Q} \in \mathbb{R}^{50 \times d}$ 생성.
2. **코사인 유사도 및 순위 계산**:
   - $\mathbf{S} = \mathbf{Q} \mathbf{D}^\top \in \mathbb{R}^{50 \times 60}$ 유사도 행렬 계산 (거리 행렬 $\mathbf{Dist} = 1 - \mathbf{S}$).
   - 각 질문 $i$마다 60개 문서 유사도를 내림차순 정렬하여, 사전에 정의된 정답 Fact ID(`expected_fact_id`)가 몇 위(Rank, 1-based)에 위치하는지 전수 검증.
3. **Reconcile 판별력 계산**:
   - 30쌍 문장에 대해 문장 A와 문장 B를 각각 인코딩하고, 코사인 유사도 $s = \frac{\mathbf{a} \cdot \mathbf{b}}{\|\mathbf{a}\| \|\mathbf{b}\|}$를 계산하여 범주별(Paraphrase, Contradict, Unrelated) 평균/최소/최대 유사도 및 분리 간격을 산출.
4. **CPU 추론 지연시간 실측**:
   - 초기 콜드 스타트 오버헤드를 배제하기 위해 워밍업(Warm-up) 1~2회 수행.
   - 단일 질의 인코딩(실시간 채팅 모사)을 3~5회 반복 측정하여 P50(중앙값) 및 P95(최대 95 백분위수) 산출.
   - 배치 인코딩(백그라운드 일괄 Fact 등록 모사)을 수행하여 배치 P50 산출.

### 2.3 무슨 기준으로 판정했는가? (평가 지표 수식 및 비즈니스 판정 기준)

| 지표명 | 계산 수식 | 측정 의미 | 페르소나 메모리 RAG 판정 기준 |
|---|---|---|---|
| **`Recall@1`** | $\frac{1}{\|Q\|} \sum_{q} \mathbb{I}(\text{rank}_q = 1)$ | 50개 질문 중 정답 Fact가 **1순위(최상단)** 에 온 비율 | 90% 이상 권장. 1순위 일치도가 높을수록 대화 프롬프트의 품질이 극대화됨. |
| **`Recall@5`** | $\frac{1}{\|Q\|} \sum_{q} \mathbb{I}(\text{rank}_q \le 5)$ | 50개 질문 중 정답 Fact가 **Top-5 이내**에 포함된 비율 | **100% 필수**. 가이드 v2에서 Top-5 기억만 프롬프트에 주입하므로 5위 밖으로 밀리면 기억 누락 발생. |
| **`MRR@5`** | $\frac{1}{\|Q\|} \sum_{q} \frac{\mathbb{I}(\text{rank}_q \le 5)}{\text{rank}_q}$ | Mean Reciprocal Rank (정답 순위 역수의 평균) | 1.0에 수렴할수록 완벽. 0.95 이상이면 최우수. |
| **`거리 마진`** | $\text{Mean}(\min_{j \neq \text{target}} d_{q,j}) - \text{Mean}(d_{q,\text{target}})$ | 오답 중 가장 가까운 거리와 정답 거리 사이의 차이 | 양수 값이 클수록 정답이 오답 후보군들과 공간상에서 뚜렷하게 분리됨. |
| **`Reconcile Gap`** | $\text{Mean}(\text{Sim}_{\text{Paraphrase}}) - \text{Mean}(\text{Sim}_{\text{Unrelated}})$ | 동일 의미 문장 유사도와 무관한 문장 유사도의 격차 | **0.40 이상 필수**. 이 간격이 좁으면(예: 0.17) 무관한 사실까지 LLM Judge로 넘어가 API 비용 폭증. |
| **`단일 P50 지연`** | $\text{Median}(\text{Time}_{\text{single\_query}})$ | 단일 사용자 발화 1건을 임베딩하는 데 걸린 CPU 시간 | **30ms 이내 최적, 최대 50ms 미만**. 100ms 초과 시 실시간 채팅 TTFT가 둔화됨. |
