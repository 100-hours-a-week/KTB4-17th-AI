📐 2. 벤치마크 설계: 무엇으로, 어떻게, 무슨 기준으로 측정했는가?

📦 ① 어떤 걸로 측정했는가?

하드웨어/런타임: Apple Silicon Mac (24GB 통합 RAM), Python 3.12, GPU 배제 CPU 실행 (프로덕션 컨테이너 환경 재현).

평가 데이터셋 (총 140건):

  • 60개 Fact 코퍼스: 취미(13), 일상(18), 연애관(11), 가치관(8), 과거이력(10)
  • 50개 구어체 질문: 단순 단어 매칭을 배제한 한국어 구어체·줄임말 질문 ("민초"↔"민트초코 쌀국수")
  • 30쌍 Reconcile 문장: 동일 의미(10쌍), 수치변경/모순(10쌍), 무관(10쌍)
⚙️ ② 어떻게 측정했는가?

문서 색인: 60개 Fact를 인코딩하여 L2 정규화된 문서 행렬 (60, Dim) 생성.

질의 검색: 50개 질문을 모델별 프롬프트 규격(Instruct/Prefix 등)에 맞춰 인코딩 후 코사인 유사도 행렬 (50, 60) 계산.

순위 검증: 각 질문별로 내림차순 정렬 후 사전에 정의된 정답 Fact ID의 순위(Rank)를 전수 집계.

CPU 지연시간: 워밍업 1~2회 수행 후 실시간 채팅 모사(단일 1건)를 3~5회 측정하여 P50/P95(ms) 산출.

🎯 ③ 무슨 기준으로 판정했는가?

Recall@5 (100% 필수): 가이드 v2에서 Top-5 기억만 프롬프트에 주입하므로 5위 밖으로 밀리면 기억 누락 발생.

MRR@5 (순위 역수 평균): 1.0에 가까울수록 가장 핵심적인 기억이 1순위(최상단)에 노출됨.

Reconcile Gap (0.40 이상 필수): 동일 의미 유사도와 무관 문장 유사도의 격차. 좁으면 무관한 기억까지 LLM 판정으로 넘어가 비용 폭증.

단일 쿼리 P50 (30ms 이내 최적): 실시간 대화 First Token 응답을 위해 임베딩 검색은 수십 ms 이내 필수.

🏁 5. 최종 결론 및 아키텍처 로드맵

1. 1차 실시간 검색 & Reconcile 최적: KURE-v1 ONNX int8 (1024d, CLS)을 가이드대로 유지합니다. 속도(16.6ms), Top-5 재현율(100%), Reconcile 분리력(0.4214), pgvector 호환성까지 현재 아키텍처에 가장 이상적입니다.

2. 초경량·초저지연 대안: NGA-KR/ko-embed-v0 (149M)는 12.2ms로 가장 빠르고 768d pgvector 호환성을 제공하므로, 리소스 제한이 극심한 환경에서 훌륭한 대안입니다.

3. 4B 및 8B 모델 (Qwen3-4B, comsat-ko-8b): 품질(Recall 98~100%)은 최상급이지만, CPU 지연시간(109ms, 238ms)과 메모리 크기(8GB, 15GB)로 인해 향후 GPU 기반 2단계 Reranker 단계로 도입하는 것을 권장합니다.
